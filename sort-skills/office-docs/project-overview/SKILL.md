# 项目概述审查

面向已有代码库的现状梳理。检查当前项目的产品形态、用途、可见功能、技术栈和结构，并生成根目录的 **项目概述.md**。本 Skill 描述代码中可观察到的现状，不负责为新项目规划需求或设计目标架构；这些任务使用 project-documentation。

## 执行原则

- 默认只读检查项目；唯一写入目标是用户要求的项目概述文档。
- 结论要有仓库内证据。区分代码或配置直接确认的信息、从命名或结构推测的信息，以及尚未确认的信息。
- 不以依赖存在、路由存在或页面占位就断言功能已完整可用。没有运行应用时，不声称已经验证运行效果。
- 不安装依赖、不运行应用、测试、构建或部署。可以从 README、清单和脚本中整理相应命令，并明确说明未执行。
- 不读取或复述 .env 等本地密钥文件的值、token、证书或个人数据。确有必要说明配置时，只描述配置项用途，不输出敏感值。
- 使用用户指定的项目范围、输出位置和语言；未指定时，使用当前项目根目录、项目概述.md 和中文。

## 执行步骤

1. **确定项目范围。** 优先根据 Git 根目录确定项目根；没有 Git 时，根据当前工作目录及项目清单、README 和入口文件定位。用户指定子目录时按指定范围审查。若仓库是 Monorepo，识别各应用或服务，并在一份概述中分别说明；无法判断用户指的是哪个子项目时再询问。
2. **收集关键证据。** 先读 README 和已有文档，再看依赖清单、锁文件中的相关包、应用配置、路由、页面入口、模块、服务层及构建配置。按需要查看代表性源文件，不必通读全部代码。跳过 .git、依赖缓存、构建产物、覆盖率和生成目录，例如 node_modules、vendor、dist、build、coverage、.next、.nuxt、.venv。
3. **识别项目形态和用途。** 根据实际配置及源代码区分 Web、原生或跨平台 App、小程序、后端服务、库或混合项目，并给出证据。结合 README、页面文案、路由、接口和模块归纳用途及功能。目标用户或业务背景若没有直接依据，应标记为推测或待确认。
4. **盘点技术路径。** 按层次检查语言与运行时、前端框架、组件库、路由、状态管理、网络请求、样式、构建工具、后端框架、数据库、认证、测试和 CI/CD。对每一项记录具体工具、用途和证据文件。结合清单、锁文件、配置和实际导入判断工具是否正在使用；只在清单中出现但未找到实际用法时，注明“已声明，实际用途未确认”。区分清单中的版本范围与锁文件解析出的版本。没有证据就写“未能从当前仓库确认”，不要猜测。
5. **说明架构与目录。** 按关键模块解释前端、后端、数据存储和外部服务的关系，只描述仓库证据支持的调用或数据流。列出核心目录和职责，保持精简；不复制完整文件清单。
6. **整理开发与工程化线索。** 从文档和 package scripts 等配置归纳安装、启动、构建、测试、检查和部署命令。说明是否找到测试、类型检查、代码规范、CI/CD 和部署配置；将“已配置”和“本次已执行”分开。本 Skill 默认不执行这些命令。
7. **生成并复核文档。** 用下面的结构作为默认参考，按项目规模删减不适用章节。文档每个重要判断都要附相对项目根目录的证据路径，或明确标为推测、未知。

## 文档结构

- **项目基本信息**：名称、项目形态、用途、目标用户（有证据时）、扫描范围和生成日期。
- **项目用途与功能清单**：按用户可见或服务能力分组，逐项说明证据及确认程度。
- **技术路径**：使用“层次、技术或工具、用途、依据”表格；准确写出已识别的框架、组件库、路由等名称。
- **架构概览**：主要模块、数据流和外部依赖；没有证据的部分不补画。
- **目录结构**：只展示关键目录，并简述各自职责。
- **开发与运行方式**：从仓库资料整理命令，并注明来源及“未执行”状态。
- **工程化现状**：测试、类型检查、CI/CD、部署等配置线索；区分有配置、未找到和未验证。
- **待确认事项**：列出影响理解项目的关键未知项，避免把它们写成结论。

使用中文和简洁表述。可用项目内相对路径（例如 README.md 或 src/router/index.ts）作为依据。不要把推测写成事实，也不要用“项目健康”“功能完整”等结论替代具体证据。

## 更新已有文档

新建文档时，用以下标记包住 Skill 生成的内容：

<!-- project-overview:generated:start -->
生成的项目概述内容
<!-- project-overview:generated:end -->

如果已有文档包含一对完整标记，只更新标记内部，保留外部内容。若目标文件已存在但没有标记，或标记不完整，先询问用户再覆盖；不要静默替换手写内容，也不要擅自换成另一个文件名。

## 完成检查

- 项目类型、框架、组件库、路由及其他工具都有对应证据；缺证据的项目明确标为推测或未知。
- 功能清单描述代码可见的入口和实现线索，不暗示未经验证的功能已经正常工作。
- Monorepo 中各子项目的技术栈和范围没有混在一起。
- 命令只来自项目资料或配置，并标清本次是否执行。
- 文档已保存到指定位置；除目标文档外没有修改被审查项目的其他文件。
- 最终简要说明生成的文件、审查范围，以及仍待确认的要点。
