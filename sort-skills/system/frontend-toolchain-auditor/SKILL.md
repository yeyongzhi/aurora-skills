# 前端开发环境体检

检查当前电脑实际可用的工具与全局 CLI，把本地证据与在线维护信息汇总成中文 Markdown 报告，回答“装了什么、正在用哪个版本、哪些可以升级、哪些需要迁移”。默认检查 Windows 当前用户环境，不宣称穷尽整机所有用户或所有 Node 版本下的安装。

## 边界与环境

- Windows PowerShell 5.1 或 PowerShell 7；未安装 Node、Git、包管理器也可以检查，不能为了体检安装它们。
- 不安装、升级、卸载、切换 Node，不修改 PATH、注册表、项目或 Shell 配置。只生成报告；查询工具可能产生自身缓存或日志，不宣称完全零磁盘写入。
- 用户要求执行升级时，将变更作为另一个任务处理，尊重已有授权及执行权限。
- 不读取或输出完整环境变量、Git 用户配置、`.npmrc`、认证令牌或私有 registry 凭据。报告只保留必要的路径、版本与脱敏错误。
- 默认联网核实更新与维护状态；用户要求离线则仅采集本地信息。网络失败标为未知，继续交付本地结果。

## 工作流程

### 1. 采集本地工具与全局包

从本 Skill 所在目录解析脚本绝对路径，不依赖用户当前工作目录。运行已有采集脚本取得基础证据：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "<skill目录>\scripts\Inspect-FrontendToolchain.ps1" -Offline
```

脚本输出是基础采集结果，不能直接作为完整最终报告：它未覆盖 Yarn/Bun 全局包、弃用信息、生命周期与完整升级判断。结合 [采集与核实说明](references/audit-guide.md) 补齐，再生成中文报告。

采集 Node.js、Git、npm、pnpm、Yarn、Bun、Corepack，以及 nvm-windows、fnm、Volta 的版本和命令路径。记录当前命令的退出码与可解析版本；失败区分“PATH 未发现”“发现但不可运行”“查询失败”。PATH 未发现不能证明系统完全未安装。

记录当前 Node 版本和架构、管理器可列出的已安装版本；不切换版本。全局包按包管理器和安装位置分别记录，默认只列直接依赖，不混入项目包或把不同环境的同名包合并。

### 2. 核实升级与淘汰状态

在线检查时读取 [采集与核实说明](references/audit-guide.md)。优先使用官方发行、registry 元数据和维护者公告，记录查询时间、来源链接、目标版本与兼容限制。不把搜索摘要当作淘汰证据。

每个全局包分别判断两个维度：

- **更新状态**：可升级、已到查询目标版本、当前版本高于目标、预发布版本、无法比较或查询失败。用 SemVer 比较，不能按字符串大小排序。主版本更新单独提示兼容风险；`latest` 标签若指向预发布版不得当作稳定版。
- **维护状态**：当前版本被弃用、包已弃用/迁移、官方停止维护、官方归档、存在维护疑虑、未发现官方淘汰证据或未知。只靠发布日期很久、下载量低或存在替代品不能判定“淘汰”。旧版有 `deprecated` 而新版无此标记，应说明旧版弃用，不能把整个包判死。

Node 同时核实官方支持周期、最新受支持 LTS 和 Current；不能仅凭 dist 列表中 `lts` 字段认定旧分支仍受支持。Git 在 Windows 优先查 Git for Windows。升级目标结合 `engines.node`、包管理器主版本、安装来源和版本管理器；有更新不等于当前环境可以直接升级。

### 3. 生成与交付报告

默认保存到当前工作目录 `frontend-toolchain-report-YYYYMMDD-HHmmss.md`；用户指定路径优先。避免覆盖同名报告。原始本机报告不写入 Skill 源目录、站点数据或 Git 历史。HTML 仅在用户要求时生成，动态内容需转义。

报告至少包含：

1. **结论**：Node/Git 是否可用及版本，全局直接依赖数量，可升级、弃用/停止维护、未确认项数量。维护风险与更新计数可重叠，说明统计范围。
2. **检查范围**：系统、架构、时间、当前用户环境、在线/离线、成功和失败的采集范围。
3. **工具表**：名称、当前版、活动路径、官方稳定目标、生命周期、更新状态、来源。
4. **Node 版本管理**：管理器、当前 Node、已安装版本、切换能力证据、PATH 冲突线索。多个路径可能是同一安装的 shim，核实后再判冲突。
5. **全局包表**：管理器/位置、包名、当前版、稳定目标、更新状态、维护状态、证据链接。清单为空与采集失败分开说明。
6. **处理建议**：优先处理已停止支持或官方弃用项，再列兼容的补丁/小版本，最后列主版本迁移。给出理由、兼容限制和可复查命令，不自动执行升级命令。没有证据时不编造替代包。
7. **未确认项**：失败、超时、私有包、无法比较、未检查的其他用户/Node 环境及复查方式。

交付报告文件的可点击链接，并用几句话说明发现与限制。若无法保存，直接交付完整报告文本并说明原因。不要只交付采集脚本输出。
