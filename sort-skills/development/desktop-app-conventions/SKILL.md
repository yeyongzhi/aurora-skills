# 桌面应用布局与设置规范

为桌面应用提供可复用的布局和设置基线，适用于单平台及跨平台项目。不限定框架；根据项目现有技术栈实现。用户明确要求优先于本规范。仅梳理需求时交付规范；要求开发时实现对应功能，不停留在界面描述。

## 规范采用方式

- **新开发的应用**：直接采用本规范，无需询问确认；实施前简要告知用户采用的布局、设置和存储约定。只有基础脚手架、尚未形成既有业务界面的项目可按新应用处理。
- **已经开发中的应用**：先检查现有实现，说明与本规范的差异、拟调整范围及影响，询问用户是否修改；确认后再实施。确认前可继续只读检查和不依赖该确认的已授权工作。
- **已有明确授权**：用户已明确要求按本规范改造或确认过调整范围时，不重复询问，按授权范围实施。仅点名或引用本技能不等于同意改造开发中的应用。
- **用户不希望调整**：保留现有方案，按用户要求继续任务，不强制套用本规范。无法判断应用阶段时，先询问是新开发还是调整现有应用。

## 使用流程

1. 按上述规范采用方式判断应用阶段并处理告知或确认，再检查现有窗口结构、导航、组件库、主题机制和偏好存储；沿用已有实现。确认目标平台，未指定时不自行扩展支持平台。
2. 根据下述布局和设置规范梳理当前差距。已有应用只调整本次涉及的部分，不擅自重做整个界面。
3. 实现所需布局、设置状态和全局样式，并让偏好在重启后保留。
4. 验证设置即时生效、持久化、系统主题响应、内部滚动和目标平台的窗口行为；汇报实现结果及尚未实现的项目。

## 组件库使用规范

本规范适用于全部页面 UI，包括业务页面、设置、导航、弹窗及浮层。默认绝大多数 UI（约 95% 的常见场景）都能由组件库覆盖；这表示组件优先的严格要求，不是允许随意留下 5% 原生控件的配额。

1. 开发前识别项目实际使用的组件库：检查依赖清单、组件配置（如 `components.json`）、已有 UI 目录和页面导入。以实际代码为依据，不仅凭安装依赖判断；明确组件库及项目已有封装的导入方式。
2. 能用组件库组件或项目基于该库的封装，就必须使用。禁止为了省事直接编写原生交互控件或自行重造库已有的 UI。
3. 项目使用 shadcn-vue 时，按钮、输入框、选择器、复选框、开关、表单、对话框、菜单、标签页、表格、提示等采用相应组件；库支持但项目尚未添加的组件，应按项目现有机制添加后使用，不能以“尚未安装”为理由改用原生控件。
4. 优先通过组件的属性、变体、插槽及组合方式满足需求，并沿用项目主题令牌。共享业务组件应复用库组件组合，不复制一套独立的基础控件样式和交互。
5. 确认组件库及现有封装确实无法满足特定需求时，才补充自定义组件，并说明缺口；优先复用库的基础交互能力，保持外观、键盘操作和可访问性一致。不擅自引入另一套组件库。

“禁止网页原生组件”指页面中直接使用原生 `button`、`input`、`select`、`textarea` 等替代可用的 UI 组件，以及用可点击 `div` 等手写同类交互。布局与语义结构仍可使用 `div`、`section`、`main` 等 HTML 元素；组件库自身内部使用原生元素不违反本规范。

### 顶部工具栏与全局滚动区域（shadcn-vue）

- 项目采用 shadcn-vue 且应用顶部提供一排工具栏时，必须使用 `Menubar` 作为工具栏组件；菜单入口与菜单内容使用其配套组件组合，沿用项目主题令牌和组件提供的键盘交互，不自行用原生控件重造菜单栏。
- 仅有标题、品牌或窗口控制的顶部区域不因此强制增加工具栏；已有应用的工具栏改造仍遵循“规范采用方式”。
- 应用内所有需要滚动的 UI 区域统一使用 shadcn-vue `ScrollArea` 或项目基于它的封装，包括主内容区、侧栏菜单、设置内容、列表、表格及弹窗中的滚动区域。此要求覆盖整个应用，不仅是设置页。
- 垂直与水平滚动均使用 `ScrollArea` 的滚动能力和配套滚动条；需要横向滚动时显式提供对应方向的滚动条，不以外层原生 `overflow-auto` 或 `overflow-scroll` 替代。
- 为滚动区域提供明确的可用尺寸，并允许父级布局和内容区收缩；各独立区域按需设置 `ScrollArea`，不把整个应用包成一个滚动区。顶部栏和侧栏底部操作区保持在滚动内容之外，避免重复滚动条和无必要的嵌套滚动。
- 滚动条外观沿用全局主题；验证鼠标滚轮、触控板、键盘及横向滚动。组件库内部的原生滚动机制属于正常实现，不需要重复包裹其内部视口；原生系统窗口与第三方编辑器自身管理的滚动需说明边界，不能通过再套一层制造双重滚动。
- 所需 `Menubar` 或 `ScrollArea` 尚未添加时，按项目现有组件添加机制补齐后使用，不以未安装为由改用原生实现。其他技术栈使用现有组件库的对应能力，不擅自引入 shadcn-vue。

### 参考图中的组件对应关系（shadcn-vue）

以下标注对应参考图的实现方式，供采用 shadcn-vue 的项目使用；其他技术栈沿用项目实际组件库。

| 界面位置 | 使用组件 | 结构与行为说明 |
| --- | --- | --- |
| 左侧主导航：首页、倒数日等 | shadcn-vue `Button` | 原生 `<nav>` 容器内排列 `Button variant="ghost"`，点击切换页面；参考实现未使用 `Sidebar` 或 `NavigationMenu` 组件。 |
| 设置分类：外观、数据与备份等 | shadcn-vue `Button` | 与主导航采用相同实现：原生 `<nav>` 容器内纵向排列 `Button variant="ghost"`，点击切换当前设置分类及对应内容，并标识当前选中项；菜单外壳使用 `Card`。具体分类仍遵循下文“设置分类”的约定。 |
| 顶部一排工具栏（如有） | shadcn-vue `Menubar` | 工具栏统一使用 `Menubar`，菜单入口与内容由其配套组件组合。 |
| 全局滚动区域 | shadcn-vue `ScrollArea` | 主内容、侧栏、设置、列表、表格和弹窗的滚动区域统一使用；按需提供垂直或水平滚动条。 |
| 侧边栏宽度下拉框 | shadcn-vue `Select` | `SelectTrigger` 显示入口，`SelectValue` 显示当前值；弹出选项由 `SelectContent` + `SelectGroup` + `SelectItem` 组成。 |

图标均来自 `@lucide/vue`，布局和间距由 Tailwind CSS 控制。原生 `<nav>` 仅承担语义容器职责，交互入口使用组件库的 `Button`，符合上述组件库使用规范。此表说明参考图的组件组合，不据此替换已有应用的导航实现；调整现有应用仍须遵循“规范采用方式”。

## 应用整体布局

### 布局适用边界

- 开发前识别应用形态，根据业务模块数量、导航层级和窗口用途选择布局，不默认所有桌面应用都采用完整侧栏。
- 多模块应用默认采用“顶部栏＋左侧导航＋主内容区”；单一功能的小工具可采用“顶部栏＋主内容区”。
- 托盘应用、菜单栏应用、悬浮窗及辅助窗口按自身用途布局，不强制增加侧栏、品牌区或独立设置分类菜单。
- 设置复杂度较低时，可使用独立窗口或对话框；设置较多时采用分类菜单。下文设置分类约定适用于采用分类菜单的设置页。
- 新应用告知布局选择及依据后实施；开发中的应用遵循“规范采用方式”，确认调整范围后实施。

### 多模块应用参考布局

参考布局采用顶部栏、左侧导航栏和主内容区；以下侧栏相关规则仅适用于提供侧栏的应用：

| 区域 | 位置与内容 | 行为 |
| --- | --- | --- |
| 品牌区 | 左上角，显示 Logo，可配应用名称 | 与侧边栏对齐，折叠时保留品牌识别 |
| 顶部功能操作区 | 顶部中间，位于主内容区上方 | 放当前页面或应用级操作；采用 shadcn-vue 且提供一排工具栏时使用 `Menubar` |
| 窗口控制区 | 顶部窗口边缘；参考图位于右上角 | 包含最小化和关闭；最大化/还原按窗口能力提供 |
| 应用菜单 | 左侧中部纵向导航 | 显示业务模块入口与当前选中项，支持收起/展开 |
| 底部操作区 | 左侧底部 | 提供侧栏收起/展开、设置入口及亮色/暗色快捷切换 |
| 主内容区 | 顶部栏下方、侧栏右侧 | 占满剩余宽度和高度，超出内容在区域内部滚动 |

- 应用外壳填满窗口；顶部栏和侧栏底部操作区保持可见，避免整个窗口页面滚动。侧栏菜单过长时独立滚动。
- 主内容区允许子布局收缩，避免长文本或列表撑开窗口；表格等确需横向滚动的内容在自身容器滚动。
- 侧栏折叠后仍保留导航图标、可识别的提示和底部操作；展开宽度由外观设置控制，折叠宽度单独定义。
- 原生标题栏或自定义标题栏依现有项目决定。跨平台应用遵循目标平台的窗口按钮位置与交互惯例，不把右上角强制用于所有系统。
- 自定义标题栏时区分可拖动区域与交互控件，保证按钮可点击。关闭窗口与退出进程的行为依产品要求确定。

## 窗口状态与关闭行为

- 主窗口默认记住上次的正常窗口尺寸、位置及最大化状态，在下次启动时恢复；不恢复为最小化或隐藏状态。
- 保存正常窗口尺寸时，使用最大化前的尺寸与位置，避免将最大化尺寸当作普通窗口尺寸。
- 恢复前检查当前显示器、可用工作区和缩放比例。显示器移除或布局变化导致窗口不可见时，将窗口调整到可见工作区内，保证标题栏和主要操作可访问。
- 设置合理的最小窗口尺寸；可调整大小的窗口在最小尺寸下仍应能完成核心操作。临时对话框和辅助窗口是否记住位置，按用途决定。
- 关闭按钮默认关闭窗口；关闭最后一个窗口后默认退出应用。需要继续驻留托盘时，应明确告知用户，并提供“关闭时收起到托盘”设置及可用的退出入口。平台惯例或用户明确要求另有约定时，按其约定实施并说明行为。
- 收起到托盘前确认托盘功能可用；不可用时采用正常关闭或退出行为，避免进程驻留却没有可操作入口。
- 存在未保存内容时，关闭窗口或退出前提供保存、放弃和取消选项；保存失败时保留内容和窗口，不直接退出。
- 多窗口应用明确窗口关闭、主窗口关闭和退出整个应用的区别；显式“退出应用”应处理所有窗口及未保存内容。
- 在实际目标平台验证窗口恢复、显示器变化、最小尺寸和关闭行为；未实际验证的项目如实标注。

## 安装与数据存储

### 默认交付和安装流程

交付桌面应用时，默认目标流程为：下载安装程序 → 打开安装面板 → 选择安装位置（例如 `D:\Program\AAA`）→ 将程序安装到该位置 → 启动使用。安装包应支持用户选择安装目录；实际打包方式须适配目标平台。平台或包格式不支持这一流程时，说明差异并确定可行方案，不宣称已支持目录选择。

默认将应用自身的可变文件放在安装根目录下，按用途分目录，不散落到其他位置：

```text
D:\Program\AAA\
├── ...程序文件
├── setting\preferences.json   # 设置偏好；也可采用项目所需的 XML 等格式
├── data\                     # 应用业务数据；JSON 或 SQLite 等按需求选择
├── backup\                   # 实现本地备份时使用
└── logs\                     # 实现日志文件时使用
```

- `setting` 和 `data` 是默认目录约定；其他目录只在实际功能需要时创建。示例中的文件名可调整。
- 使用统一路径解析，以安装根目录为基准拼接绝对路径，不依赖启动时的当前工作目录，不硬编码示例盘符。开发环境的数据根目录单独配置，不向源码或打包资源写入运行数据。
- 设置和业务数据默认采用真实本地文件；不能仅用 WebView 的 localStorage、IndexedDB 或框架默认用户数据目录代替上述目录约定。已有应用采用其他路径时，先识别现状，迁移需保留原数据，不擅自搬移。
- 安装前或首次运行时检查数据目录可写性。受保护目录、只读应用包或沙箱限制导致不可写时，向用户说明并让其选择可写安装位置或替代数据根目录；不得静默改到其他位置，也不要求每次以管理员身份运行。
- 数据设置页展示实际数据位置；外部笔记目录单独展示。跨平台实现要核实目标平台可写路径与打包限制。
- 升级不得覆盖 `setting`、`data` 或用户笔记。卸载默认保留用户数据，清除数据须由用户明确选择。

### 根据功能选择存储方式

| 场景 | 默认选择 | 说明 |
| --- | --- | --- |
| 本地笔记、Markdown 文档管理 | 用户选择的本地文件夹与 `.md` 文件 | 文件夹组织笔记，文档直接读写；不为笔记正文或目录额外建立数据库 |
| 设置偏好、简单配置、小规模结构化数据 | JSON；已有格式需要时可用 XML | 结构清晰、关系简单且无需复杂查询时，优先使用文件 |
| 存在关联关系、复杂查询、事务或大量结构化记录的功能 | 按实际需要选择 SQLite 等数据库 | SQLite 文件放在 `data` 中，不把数据库作为所有功能的默认依赖 |

- 笔记目录由用户选择，可以位于安装目录之外；这是用户文档存储位置，与应用自身的 `setting`、`data` 分开。不能强制将用户选中的笔记复制进安装目录。
- 开发其他功能前，按数据规模、关系、查询及一致性需求选择 JSON 或数据库，并简要说明依据。没有数据库需求时不引入数据库；确需全文索引等额外能力时，另行说明方案，不改变 Markdown 文件作为文档真源的约定。
- JSON/XML 保存应避免中途写入造成文件损坏；数据库写入使用适当事务。读取失败时保留原文件并报告，不能用默认值直接覆盖损坏数据。
- SQLite 使用期间的 WAL、SHM 等辅助文件应与数据库路径协调；备份采用一致性备份方式，不能只复制一个正在写入的数据库文件就宣称备份完整。

## 设置分类

采用分类菜单的设置页使用独立分类导航；采用 shadcn-vue 时，与主导航一样使用原生 `<nav>` 容器和 `Button variant="ghost"`，纵向排列分类入口，点击切换对应内容并标识当前选中项。默认包含以下分类；其他分类按业务需要增加：

| 分类 | 职责 |
| --- | --- |
| 外观 | 外观模式、主题色、侧边栏宽度、全局圆角、全局字体大小 |
| 数据 | 数据存储位置、导入/导出、数据管理等应用数据相关选项 |
| 备份 | 备份位置、手动备份、恢复；自动备份、周期及保留数量按需求提供 |
| 关于 | 应用名称、版本、简介；许可、项目链接、更新入口按项目能力提供 |

分类是组织基线，数据与备份的具体功能依业务确定，不因列出分类就自动增加同步服务、自动更新或破坏性清理功能。没有实现的能力不显示为可操作按钮。设置入口默认打开外观页，可保留用户上次访问的分类。

## 外观设置：默认基线

- 常规桌面应用默认提供外观模式、主题色、全局圆角和 UI 字号；存在可调宽度的侧栏时，再提供侧边栏宽度。
- 没有侧栏、侧栏仅显示图标或宽度必须固定时，不显示侧边栏宽度设置，也不保留无效控件。
- 全局字体大小作用于导航、设置、按钮、表单等应用 UI。编辑器正文、终端、阅读内容及画布文字可提供独立字号，不随 UI 字号强制变化；未提供独立设置时，应明确其继承关系。
- 原生窗口边框和系统控件遵循平台能力；自绘界面中的主题、圆角和字号统一应用。
- 托盘菜单、悬浮窗等受限界面按实际能力提供有效选项。省略默认设置项时，简要说明原因；不能仅因实现方便而省略。
- 保留下表圆角和字号选项及默认值，验收仅检查当前应用适用的设置项。

适用的设置项必须提供真实可用的控件，并统一影响对应的应用界面。

| 设置项 | 控件 | 选项与默认值 |
| --- | --- | --- |
| 外观模式 | 单选或 Select | 亮色、暗色、跟随系统；建议默认跟随系统 |
| 主题色 | 可选择的色块或 Select | 提供若干主题色，例如红、橙、黄、绿、青、蓝、紫；默认色沿用产品品牌 |
| 侧边栏宽度 | Select | 建议 200、220、240、260、280、320 px，默认 240 px；可按应用调整 |
| 全局圆角 | Select | 直角 · 0 px、微圆角 · 4 px、小圆角 · 8 px、中圆角 · 12 px、大圆角 · 16 px（默认）、超大圆角 · 24 px |
| 全局字体大小 | Select | 12 px、14 px（默认）、16 px、18 px、20 px、24 px |

圆角和字体大小的选项及默认值来自参考图，应保留；模式默认值、主题色集合和侧栏宽度是初版建议，用户另有要求时替换。Select 显示当前值，展开后标识选中项；支持键盘选择与可访问标签。

### 外观模式与快捷切换

- 保存用户选择的模式和实际解析出的亮/暗主题之间的区别。跟随系统时监听系统变化；选择固定亮色或暗色后不再随系统变化。
- 提供外观快捷切换时，与设置页共用同一状态，禁止各自维护主题；有侧栏时默认放在侧栏底部，无侧栏时按布局提供合适入口。
- 快捷切换将当前实际主题切换到相反的固定模式，并同步设置页；用户可在设置页重新选择跟随系统。
- 启动时尽早读取偏好并应用主题，减少先亮后暗的闪烁。

### 全局样式与偏好存储

- 通过统一样式变量、设计令牌或框架主题机制管理主题色、圆角和字号，覆盖导航、按钮、表单、卡片、弹窗及浮层，而非仅修改设置页。
- 主题色使用能适应亮暗背景的色阶；选中态除颜色外还用勾选、边框或文字标识，并保证文字与背景可辨识。
- 圆角作为基础令牌，可按组件大小派生；圆形头像、胶囊和窗口原生边框依自身语义处理。
- 字号作为应用 UI 的正文基础字号，标题及辅助文字按比例或语义层级派生。字号增大时控件与间距应能容纳文字，避免固定高度导致截断。
- 建议偏好字段为 `appearanceMode`、`themeColor`、`sidebarWidth`、`borderRadius`、`fontSize`，字段名可适配项目已有模型。
- 偏好存储遵循“安装与数据存储”中的 `setting` 目录约定；已有项目先识别其存储方案并保留数据。保存后立即生效并在重启后恢复。校验读取值，损坏或不支持的值回退到默认；不能把设置值直接拼入任意样式或路径。

## 验收要点

- 安装流程支持目标平台约定的目录选择；设置与业务数据实际写入约定目录，重启及升级后保留。不可写路径有明确处理。
- 笔记功能直接使用用户选择的文件夹和 Markdown 文件；其他功能的存储方式有需求依据。

- 所有新增或修改页面遵循已识别的组件库；未直接使用原生交互控件替代库内可用组件。自定义组件有明确的库能力缺口依据。

- 采用 shadcn-vue 时，顶部一排工具栏使用 `Menubar`，菜单展开和键盘交互可用。
- 应用内滚动区域统一使用 `ScrollArea`；垂直及所需水平滚动有效，无重复滚动条或无必要的嵌套滚动。主内容超高时内部滚动，顶部和底部操作区保持可用；菜单超高时底部入口不被挤出。
- 布局符合应用形态；提供侧栏时，其收起/展开及适用的宽度选择生效，折叠后仍能进入设置。
- 适用的亮色、暗色及跟随系统均可用；系统变化与所提供的快捷切换符合上述规则。
- 适用的外观偏好即时作用于业务页与弹窗，重启后保留；圆角和字号选项、默认值正确，独立内容字号的继承关系明确；省略项有依据。
- 最大 UI 字号下导航和设置控件仍可使用；有可调侧栏时同时验证最窄侧栏组合。
- 最小化、关闭及所提供的其他窗口控制在实际目标平台有效，不能仅通过网页预览宣称原生窗口行为已验证。
- 窗口尺寸、位置和最大化状态按约定恢复；显示器变化后窗口可见，最小尺寸下核心操作可用。
- 关闭、退出及所提供的托盘行为符合约定；未保存内容可保存、放弃或取消，保存失败不会丢失内容；未实际验证的窗口行为如实标注。
