# 应用品牌命名

从产品价值出发，交付可以一起使用的品牌名、副标题和 Slogan。只提供一个目标仓库或一段描述也能执行，不要求用户先填品牌问卷。

## 输入与产品理解

- **仓库输入**：只读查看 README、产品文档、入口界面、主要业务流程及必要的代码。关注实际服务谁、解决什么问题、核心体验和差异；技术栈、目录名和 package 名不能替代产品定位。远程仓库用可用工具读取；访问失败时说明缺失并请求描述，不假装读过代码。
- **描述输入**：提炼目标用户、使用场景、核心任务、用户收益和产品气质。区分用户明确给出的事实与合理推断，不把想象中的功能写成现有能力。
- 输入足够时直接开始。信息不完整但仍能形成定位时，简短声明假设并继续；只有无法判断产品用途或存在决定性歧义时，问一个关键问题。
- 默认用中文解释、副标题和 Slogan；品牌名用英文。用户指定市场、语言、已有词根或风格时优先遵循。

先用一两句话概括：这是为谁设计的什么产品，帮助用户得到什么结果。后续命名应能回扣这段定位。

## 品牌名原则

1. **优先两个以空格分隔的英文单词**，例如 `Mark Flow`、`Lumo Hub`。这是优先方向而非绝对限制；只有明显更适合产品或用户明确指定时才采用其他形式，并简述理由。大小写不作硬性限制，默认选择易读、统一的展示形式。
2. 可以组合常用词、隐喻词、相关意象或自造词。自造词可以承担品牌识别，不必有字典释义；明确写成“自造名称”或“联想到……”，不要编造词源、翻译或历史含义。
3. 名字体现用户收益、体验、任务或产品气质，而不只是功能名的机械翻译。描述性名字便于理解，意象型名字便于建立品牌；根据定位选择平衡。
4. 第二个词应提供有用的语义或节奏。`Flow` 可暗示连贯过程，`Hub` 可暗示聚合中心，但不要对所有软件套用同一种后缀，也不要被示例限定词库。
5. 检查读音、拼写、记忆难度、两词搭配是否自然、明显负面联想和未来适度扩展的空间。优先可口头传播、容易输入的短名称；避免难读拼接、空泛流行词堆叠和与实际产品不符的品类暗示。
6. 名字、副标题、Slogan 分工明确：名字负责识别，副标题说明产品是什么，Slogan表达用户能获得的价值或感受。

## 形成方案与选择

围绕产品形成若干不同方向，例如任务与结果、体验与意象、自造品牌词与品类提示。内部比较后，默认展示一个首选和两个有实际区别的备选；用户只要一个或指定数量时按其要求交付。

按这些维度择优，不用虚构精确评分：

- 产品契合：能否解释它为什么属于这个产品，而不是任何应用都能用。
- 辨识与传播：是否容易读、记、写，与备选是否有实质区别。
- 预期准确：是否让人误解用途、受众或产品规模。
- 扩展空间：不把品牌锁死在一个偶然的实现细节，也不牺牲当前产品的清晰度。

每个展示的候选都配套完整副标题和 Slogan，不只列名字。首选理由必须指向产品定位和命名取舍，避免“高级、好听、有科技感”这类没有证据的评价。

## 副标题与 Slogan

- **副标题**：用简短、自然的一句话说明产品类别或核心用途，让首次看到名字的人知道它做什么。中文通常控制在约 8–18 字，以表达清楚为先，不硬凑字数。
- **Slogan**：表达核心收益、行动结果或情绪体验，适合放在首页或介绍页。中文通常约 6–16 字，避免复述副标题或塞入所有功能。
- 文案基于输入证据，避免“全球第一”“绝对安全”“十倍效率”等无依据承诺。不要为了押韵而牺牲含义。

## 交付格式

先写简短产品定位，再直接给出首选：

> **品牌名**：两个英文词
>
> **副标题**：产品是什么或用来做什么
>
> **Slogan**：用户价值或体验

接着用两三句话说明名字的含义或联想、为何适合目标用户，以及名字与两段文案如何配合。备选可用表格展示“品牌名 / 副标题 / Slogan / 命名方向”，避免大量低质量候选稀释推荐。

最后标明重名核查状态。命名创作可离线完成；不要将未检索的名称写成“唯一”“可注册”或“域名可用”。用户要求核查，或适用环境要求联网验证时，搜索名称及软件领域的明显同名，注明实际查询范围与发现；搜索结果不能代替商标、域名和应用商店的完整可用性核验。未核查时只需简短写“尚未核查重名及注册可用性”。

默认在对话中交付；只有用户要求保存文件时才写入指定位置。输入仓库仅用于理解产品，不自动修改应用名、配置、代码或发布内容。
