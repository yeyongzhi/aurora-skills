# 标题（中文名 · my-skill）

一段话说清这个 skill 解决什么问题、产出什么。**第一句话就要让 Agent 判断出该不该继续往下读。**

## 适用环境

操作系统、依赖、前置条件。需要联网吗？需要什么权限？有没有版本要求？

## 执行步骤

1. 第一步，要具体到可以直接做。
2. 第二步。
3. 产出结果后，用 `present_files` / 打印 / 写文件的方式交付。

有脚本就写清楚调用命令和参数表：

| 参数 | 作用 | 示例 |
| --- | --- | --- |
| `-Path` | 目标路径 | `-Path D:\data` |

## 注意事项

- 容易踩的坑、耗时预估、边界条件。
- 失败时的降级路径。

## 安全红线

涉及删除、覆盖、外发（邮件 / 推送 / 公开发布）、花钱的操作，必须在这里写明红线。默认只读、默认先确认。

## frontmatter 字段说明

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `name` | 是 | kebab-case，**必须与所在目录名完全一致**，否则 lint 报错 |
| `description` | 是 | 触发条件，见下方写法 |
| `platform` | 否 | `all`（默认）/ `windows` / `macos` / `linux`，可逗号分隔 |
| `tags` | 否 | 交叉检索用，弥补"一个 skill 只能归一类"的限制 |
| `version` | 否 | 语义化版本，破坏性改动时 +1 |

### description 怎么写

Agent 靠 `description` 决定是否加载，写不好等于这个 skill 不存在。公式：

> **做什么** + **什么时候用（触发场景清单）** + **边界（不适用什么）**

- 触发词要覆盖用户的**口语说法**，中英文都写。用户不会说"磁盘空间分析"，会说"C 盘满了"。
- 加上「即使没有明确说 X，也应使用本 skill」这类兜底句，能显著提高命中率。
- 别写成营销文案，别超过 4 行。
