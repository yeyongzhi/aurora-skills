# 前端开发环境体检

检查 Windows 当前可用的前端开发工具链，区分“已安装版本”“可切换版本”“可用稳定版更新”和“无法确认”，最终给出有依据、可执行但不自动执行的升级建议。

## 默认边界

- 默认只读：不得安装、升级、卸载、清理全局包，也不得修改 PATH、注册表、Shell 配置或项目文件。
- 只有用户明确要求执行升级后，才进入变更流程；升级前列出目标、当前版、目标版、来源、影响和回滚方式，并按实际权限要求取得确认。
- 不把预览版、RC、beta、nightly 当作稳定版推荐。Node.js 同时报告最新 LTS 与最新 Current；默认优先建议 LTS。
- 不能联网或版本源失败时保留本机核查结果，标记“在线版本未知”，不得把未知写成“已是最新”。

## 核查范围

1. **基础工具**：Node.js、Git。
2. **Node 版本切换能力**：nvm-windows、fnm、Volta；如果没有版本管理器，说明当前 Node 不能通过已发现的管理器切换，不等同于系统绝对无法切换。
3. **包管理器**：npm、pnpm、Yarn、Bun、Corepack。
4. **全局 Node 依赖**：分别从已安装的 npm、pnpm、Yarn 获取；不要把项目本地依赖混入全局清单。
5. **升级信息**：优先使用工具自己的官方 registry / release 信息；Git 可辅以 WinGet 的精确包结果。报告来源和查询失败项。

## 执行

优先运行随 skill 提供的脚本：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Inspect-FrontendToolchain.ps1
```

常用参数：

| 参数 | 用途 |
| --- | --- |
| `-Offline` | 只采集本机版本，不查询稳定版和 outdated 信息 |
| `-OutputPath <路径>` | 另存为 UTF-8 Markdown 报告；不传则打印到终端 |

如果脚本因环境限制无法运行，使用等价的只读命令逐项检查，并保持相同报告结构。不要仅凭 `where.exe` 判断安装状态；以命令可执行且能返回版本为准，同时记录解析到的命令路径，以识别多套安装冲突。

## 判断规则

- **已安装**：命令成功返回可解析的版本。
- **存在多版本风险**：同一工具解析到多个路径，或版本管理器的 active 版本与 `Get-Command` 路径明显不一致。
- **可切换**：至少发现一个可工作的 nvm、fnm 或 Volta。列出已安装版本与当前激活版本；不主动切换。
- **可升级**：在线来源明确给出高于当前版本的稳定版本。仅版本字符串不同但无法可靠比较时写“建议人工确认”。
- **全局包可升级**：包管理器的 outdated 结果明确给出 stable/latest 目标。若目标带预发布标识，单独列出且不推荐。
- 对 Node.js 的主版本升级提示潜在破坏性；对 Git、包管理器和全局 CLI 的升级提醒检查现有脚本或 CI 兼容性。

## 输出格式

报告至少包含：

1. 总览：系统时间、PATH 中发现的工具、是否完成在线检查。
2. 工具表：工具、当前版本、命令路径、最新稳定版、状态。
3. Node 版本管理：管理器、当前版本、已安装版本、是否可切换。
4. 全局依赖：来源包管理器、包名、当前版、目标稳定版、状态。
5. 建议：按“安全补丁更新 → 小版本更新 → 主版本/环境变更”排序。
6. 未确认项：查询失败原因和可复查命令。

结论应明确回答：Node 是否安装及版本、能否切换、是否有稳定版更新；Git 是否安装及版本、是否可升级；发现了哪些全局依赖、哪些存在稳定版更新。
